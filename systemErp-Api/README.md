# ERP Backend — ASP.NET Core 9 / EF Core 9 / SQL Server

Backend لثلاثة أنظمة تعمل فوق أساس مشترك: **المحاسبة العامة** و**معرض السيارات** و**نقاط البيع (POS)**،
مبني حول واجهة Angular الموجودة (`SystemErp-web`) التي هي مصدر الحقيقة للمتطلبات.

```
src/
├── ERP.Api/         Controllers/<System>/<Feature>/XController.cs  (ملف لكل controller)
├── ERP.Service/     Services/<System>/<Feature>/XService.cs · Data/ (DbContext + Migrations)
└── ERP.Core/        Models · DTOs · Contracts  ← كلٌّ منها: <System>/<Feature>/<Type>.cs (ملف لكل نوع)
tests/ERP.Tests/     Shared · Accounting · CarShowroom · POS · Architecture
docs/                ARCHITECTURE · FRONTEND_MAPPING · API_ENDPOINTS
```

مثال: بيانات العملاء الأساسية = `Controllers/Shared/MasterData/CustomersController.cs` + `Services/Shared/MasterData/CustomerService.cs` + `Contracts/Shared/MasterData/ICustomerService.cs` + `DTOs/Shared/MasterData/{CustomerDto,CreateCustomerDto,UpdateCustomerDto}.cs` + `Models/Shared/MasterData/Customer.cs`. الأنظمة: Shared · Accounting · CarShowroom · POS.

## التشغيل

```bash
# 1) الإعدادات (أسرار خارج المستودع)
dotnet user-secrets init --project src/ERP.Api
dotnet user-secrets set "Jwt:Key" "<32+ chars>" --project src/ERP.Api
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "<sql server>" --project src/ERP.Api

# 2) قاعدة البيانات
dotnet ef database update --project src/ERP.Service

# 3) التشغيل (Development يفعّل Swagger والترحيل التلقائي و CORS لـ http://localhost:4200)
dotnet run --project src/ERP.Api
```

في Development يوجد مفتاح JWT تجريبي في `appsettings.Development.json` — **لا تستخدمه خارج جهازك**.

## إعدادات الإنتاج الإلزامية

كلها أسرار/إعدادات بيئة (متغيرات بيئة أو مخزن أسرار)، لا تُكتب في المستودع:

| الإعداد | الغرض |
|---|---|
| `Jwt:Key` | مفتاح توقيع الجلسات (32 حرفاً فأكثر) |
| `ConnectionStrings:DefaultConnection` | قاعدة البيانات |
| `Email:UserName` / `Password` / `FromAddress` | بريد إرسال رموز استعادة كلمة المرور |
| `DataProtection:KeysPath` | مجلد دائم لمفاتيح تشفير أسرار بوابات الدفع؛ بدونه تضيع عند نقل الخادم أو إعادة بنائه |
| `Auth:RateLimitPerMinute` | حد محاولات الدخول/التسجيل/الاستعادة لكل عنوان IP في الدقيقة (الافتراضي 20؛ 0 = بلا حد) |
| `Cors:Origins` | عناوين الواجهة المسموحة |

الخادم يعمل خلف وسيط عكسي يتولى HTTPS (يُقرأ عنوان العميل من `X-Forwarded-For` ويُفعَّل HSTS خارج التطوير).

## قواعد سلامة الدفاتر

- **الفاتورة المرحّلة مقفلة:** لا تُعدَّل ولا تُحذف؛ تُصحَّح بمرتجع (إشعار دائن/مدين). المسودة برقم مؤقت `DRAFT-…` والرقم المتسلسل يُصرف عند الترحيل فلا فجوات. إلغاء عملية نقطة البيع يصدر إشعاراً دائناً كاملاً.
- **إقفال الفترات والسنة:** `/fiscalperiods` — تاريخ إقفال الدفاتر يرفض أي قيد أو فاتورة أو حركة مخزون بتاريخ داخله، وإقفال السنة يرحّل نتيجتها إلى الأرباح المبقاة (32) بقيد واحد.
- **التزامن:** رصيد الحساب ورصيد الصنف محميان برمز تزامن؛ المعاملة المتعارضة تُعاد تلقائياً ثم تُرفض بـ 409.
- **العملة:** الدفاتر والمخزون بالعملة الأساسية؛ فاتورة العملة الأجنبية تُحوَّل بسعر صرفها.
- **المشتريات:** بنود الخدمات إلى حساب مصروف (524) لا المخزون، ومرتجع المشتريات يخرج بالتكلفة والفرق إلى فروق أسعار المشتريات (514).
- **الأرصدة الافتتاحية:** رصيد العميل/المورد/البنك الافتتاحي قيدٌ مقابل حساب الأرصدة الافتتاحية (33)، فيظهر في ميزان المراجعة.
- **السداد والفواتير:** السند يُوزَّع على فواتير آجلة (`allocations`)، ومنه المتبقي على كل فاتورة (`amountDue`) وأعمار الديون `/reports/Aging`؛ غير الموزَّع دفعة مقدمة.
- **الأصول الثابتة:** قيمة تخريدية، استبعاد ببيع أو شطب (`/fixedassets/{id}/dispose`) بقيد ربح/خسارة، وعكس ترحيل إهلاك (`/fixedassets/depreciation/{journalEntryId}/reverse`) يعيد أرصدة الأصول. قيود الإهلاك والاستبعاد لا تُعكس من شاشة القيود.
- **سند بضريبة:** `vatAmount` في سند صرف/قبض لمصروف أو إيراد مباشر يُقيَّد في حساب الضريبة ويدخل الإقرار.
- **إيراد السطر:** كل سطر مبيعات يُرحَّل إلى حساب إيراده (`revenueAccountCode`) ومركز تكلفته.
- **تسوية المخزون:** التسوية اليدوية ترحّل قيداً بقيمتها (المخزون مقابل فروقات الجرد 513، أو `counterAccountCode` مثل 33 لمخزون أول المدة)، وتعديلها/حذفها يعكسه.
- **اقتناء الأصل:** `acquisitionAccountCode` عند تسجيل الأصل يرحّل قيد اقتنائه؛ والمركز المالي `/reports/BalanceSheet` يُبنى من سطور القيود.
- **سجل التدقيق:** ترحيل الفواتير وحذف مسوداتها، وإنشاء/تعديل/حذف السندات والقيود اليدوية وعكسها.
- **الضريبة:** لكل سطر تصنيف ضريبي (أساسي/صفري/معفى/خارج النطاق) وسبب إعفاء برمز الهيئة (`vatExemptionReasonCode`، القائمة من `/invoices/VatExemptionReasons`)؛ الإقرار `/reports/VatReturn` يُحسب من السطور ويفصل الصادرات ويضيف تسويات القيود اليدوية على حسابي الضريبة. الفاتورة الضريبية تشترط اسم المشتري ورقمه الضريبي وعنوانه الوطني. وقت الإصدار بتوقيت المملكة ويُرمَّز في QR بالتوقيت العالمي. المنفَّذ من ZATCA هو المرحلة الأولى (رمز QR) فقط.
- **المخزون لكل مستودع:** لكل صنف رصيد في كل مستودع (`/stockmovements/WarehouseStock`) ومجموعها رصيد الصنف؛ التكلفة موحّدة للصنف. المستند بلا `warehouseId` يستخدم المستودع الافتراضي، والصرف يتحقق من رصيد مستودعه، والمرتجع يعود إلى مستودع فاتورته، والجرد يقارن برصيد مستودعه. التحويل بين المستودعات `/stocktransfers` ينقل الكمية بلا أثر على التكلفة أو الدفاتر.
- **مستودع المستندات والتقارير:** عرض السعر وأمر البيع/الشراء وبيان التسليم تحمل `warehouseId` وينتقل إلى فاتورتها؛ وتقارير `InventoryAudit` و`ItemMovements` و`ItemLedger` تقبل `warehouseId` (تظهر فيه التحويلات).
- **القوائم المالية:** `/financialstatements/IncomeStatement` و`FinancialPosition` و`CashFlow` من سطور القيود المرحّلة لفترة، مع فترة مقارنة اختيارية (`compareFrom/compareTo` أو `compareAsOf`). قيود إقفال السنة لا تدخل قائمة الدخل، والتدفقات بالطريقة المباشرة من الحساب المقابل لكل حركة نقد.
- **التسوية البنكية:** `/bankreconciliations` — ورقة عمل بحركات الحساب غير المطابَقة، والاعتماد يُرفض ما لم يساوِ رصيد المطابَق رصيد الكشف. القيد المطابَق لا يُعدَّل ولا يُحذف، ولا يُلغى إلا آخر تسوية للحساب.
- **الرواتب:** `/employees` و`/payroll` (معاينة، ترحيل، عكس) — مسير واحد مرحَّل لكل شهر بقيد: مدين 526 و527، دائن 214 و215. نسب التأمينات تُضبط لكل موظف ولا تُفترض في الكود.
- **سجل التدقيق التلقائي:** كل إنشاء/تعديل/حذف لمستند أو بيان أساسي أو إعداد يُسجَّل في المعاملة نفسها مع المستخدم والقيم «قبل ← بعد» (`AuditTrailInterceptor`)؛ تغيّر الأرصدة والكميات الذي يُحدثه النظام لا يُعدّ تعديلاً.

## دفع الاشتراكات (Paymob)

تسجيل منشأة جديدة (`POST /auth/RegisterCompany`) يبدأ **فترة تجريبية مجانية لمدة شهر** على الباقة المختارة بلا دفع
(`SubscriptionCatalog.TrialMonths`). الواجهة تنبّه قبل انتهائها بأسبوع، وبعد انتهائها يحجب الخادم كل شيء عدا الدخول والاشتراك
والدفع (`SubscriptionDto.TrialEnded`) حتى يُسدَّد الاشتراك. السداد عبر `POST /payments/subscription`، والاشتراك المدفوع يُفعَّل فقط
بإشعار Paymob الموقَّع (HMAC) المطابق للمبلغ والعملة؛ السداد قبل نهاية التجربة يضيف أيامها الباقية إلى المدة المدفوعة.
التفعيل اليدوي (تحويل بنكي مثلاً) يجريه مدير المنصة من لوحة المنصة.

**الإعدادات** — نفس المسار الرسمي (صفحة الدفع المستضافة لدى Paymob + إشعار موقَّع) في التطوير والإنتاج؛ الفرق في المفاتيح فقط:
مفاتيح **وضع الاختبار (Test mode)** من لوحة Paymob للفحص، والمفاتيح الحية في الإنتاج. لا توجد شاشة دفع محاكاة في النظام.

| الإعداد | القيمة |
|---|---|
| `Paymob:SecretKey` / `PublicKey` / `HmacSecret` | مفاتيح حساب Paymob الخاص بالمنصة (Test mode للفحص، Live للإنتاج) |
| `Paymob:IntegrationIds` | أرقام التكامل مفصولة بفواصل (بطاقات / مدى / Apple Pay) — لكل وضع أرقامه |
| `Paymob:PublicApiUrl` | العنوان العام للـ API (https)؛ يُضبط في لوحة Paymob كـ Transaction processed callback: `{PublicApiUrl}/api/v1/payments/paymob/webhook` |
| `Paymob:FrontendUrl` | عنوان الواجهة (صفحة العودة `/payment-result`) |

كلها أسرار/إعدادات بيئة لا تُكتب في المستودع. للفحص محلياً بمفاتيح الاختبار:

```bash
dotnet user-secrets set "Paymob:SecretKey" "<sk_test_...>" --project src/ERP.Api
dotnet user-secrets set "Paymob:PublicKey" "<pk_test_...>" --project src/ERP.Api
dotnet user-secrets set "Paymob:HmacSecret" "<HMAC من لوحة Paymob>" --project src/ERP.Api
dotnet user-secrets set "Paymob:IntegrationIds" "<رقم تكامل الاختبار>" --project src/ERP.Api
dotnet user-secrets set "Paymob:PublicApiUrl" "<رابط https عام يصل للـ API المحلي، مثل نفق ngrok>" --project src/ERP.Api
```

`Paymob:FrontendUrl` مضبوط في `appsettings.Development.json` على `http://localhost:3000`. الدفع في وضع الاختبار يتم ببطاقات الاختبار
التي تنشرها Paymob في لوحتها/توثيقها ولا يُخصم أي مبلغ. الإشعار يجب أن يصل للخادم: بلا `PublicApiUrl` عام تبقى العملية «معلّقة» ولا يُفعَّل الاشتراك.
نقص أي إعداد يوقف سداد الاشتراكات (409) ويُسجَّل تحذير عند الإقلاع.

## ما يغطيه

- **مشترك:** المصادقة (JWT، تسجيل منشأة، استعادة كلمة المرور OTP)، الصلاحيات حسب الشاشة، العملاء/الموردون/البنوك (بحساب أستاذ تلقائي)، الأصناف والمخزون بأربع طرق تكلفة، الموافقات، الإشعارات، الاشتراكات.
- **المحاسبة:** شجرة الحسابات، قيود يدوية/آلية مع العكس، السندات، فواتير البيع/الشراء/المرتجعات (ZATCA QR)، عروض الأسعار، طلبات الشراء، الأوامر، الاتفاقيات، العقود بمراحلها والمستخلصات، بيانات التسليم، ميزان المراجعة وكشف الحساب والإقرار الضريبي وتقارير المخزون.
- **معرض السيارات:** بيانات الماركات→الموديلات→الفئات→السنوات، المركبات (VIN)، دورة الشراء (7 مراحل) بإنشاء المركبات وترحيل التكاليف المحمّلة، دورة البيع (5 مراحل) بحجز المركبة وضريبة هامش الربح، 8 تقارير.
- **POS:** الورديات وفرق الصندوق، البيع بتسعير وعروض وكوبونات في الخادم، الدفع المقسّم، الولاء، السلال المعلّقة، المرتجعات، الإعدادات — والبيع فاتورة محاسبية حقيقية (مصدر واحد للحقيقة).
